# Unity POC 구현 실행 프롬프트

다음 작업을 수행해 주세요.

`POC_CORE.md`는 ZDeffencePlan / PZDeffencePlan을 통합한 **Unity 재미 검증 POC의 단일 기준서(SSOT)**입니다. **구현 전에 전체 문서를 읽고**, 특히 **0절(압축 필수 핵심), 2절(불변 원칙), 3절(확정 규칙), 7절(검증 조건), 8절(결정 기록)**을 작업 기준으로 삼으세요. 현재 대화가 압축되거나 다른 워커에게 인계되어도 이 문서를 다시 읽어 같은 판단을 유지해야 합니다.

## 수행 지시

1. 현재 저장소/Unity 프로젝트의 실제 상태를 조사하고, 이미 구현된 부분을 재사용하세요. 기획 저장소의 Unreal Engine 관련 기술 지시는 적용하지 말고, 문서에 정의된 Unity 6 · URP · C# · Input System · NavMesh · UGUI 방향으로 구현하세요. 프로젝트 버전과 충돌하는 부분은 현재 프로젝트 설정을 우선 확인하세요.
2. **재미 검증 수직 슬라이스부터** 구현하세요: `생존자 선택/명령 → 평시 작업 배정 + 전시 방어 배정 → 공습 경보 자동 전환 → 실시간 전투 → 영구 사망의 다음 웨이브 이월`. 이 흐름이 동작하기 전에는 가챠, 스토리, 아트, 범용 프레임워크에 착수하지 마세요.
3. 그다음 **자원 생산 → 방벽/감시탑 건설 → 오프맵 탐사(웨이브와 시간상 겹침) → 3웨이브 완결 → 승패/재시작**을 연결하세요. 중요한 선택은 실제 인력 배분과 위치 지정에서 나오게 하며 카드식 강화 선택지로 대체하지 마세요.
4. **프리미티브 기반 단일 맵과 최소 HUD**만 제작하세요. 생존자별 상태, 작업/방어 배정, 파견 중 이탈, 핵심 시설 HP, 스크랩, 웨이브 경보, 사망 결과가 바로 보이도록 하세요.
5. 설정값은 빠르게 바꿀 수 있게 유지하고, **고정 난수 시드와 최소 이벤트 로그**로 같은 조건의 테스트를 지원하세요. 검증한 것과 아직 실플레이로 검증하지 않은 것을 명확히 구분하세요.
6. 범위 추가 요구나 기획 충돌이 발견되면 **`POC_CORE.md`의 불변 원칙과 결정 기록에 먼저 대조**하고, 필요시 변경 사유/영향을 남기세요. 에이전트가 임의로 POC를 MVP 규모로 확장하지 마세요.

## 완료 보고 형식

- **구현 현황:** 동작 확인한 기능 / 미완성·제약 사항
- **재생 방법:** Unity 프로젝트 열기 → 씬 실행 → 조작 및 플레이 절차
- **검증 결과:** `POC_CORE.md`의 7절 수락 조건별 통과·미통과와 직접 확인한 근거
- **핵심 경험:** 인력 배분, 방어 배치, 영구 손실의 인과 관계가 실제로 확인되었는지 (플레이테스트 이전이면 미검증이라고 명시)
- **변경/판단:** 문서와 충돌한 결정 및 추후 확인할 이슈

**최상위 목표:** 가능한 많은 시스템을 구현하는 것이 아니라, `인력 운용 → 방어 결과 → 영구 손실 → 다음 인력 운용`의 재미를 가장 작고 명확한 Unity POC로 검증하는 것입니다.
