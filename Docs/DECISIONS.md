# 착수 결정 기록

> 2026-11-06 구현 착수 전 사용자와 확정한 결정. `POC_CORE.md` 8절 결정 기록(DEC-01~12)을 잇는다.
> 문서 우선순위는 `POC_CORE.md` 0절 11항을 따른다.

## 게임 규칙

| ID | 확정 결정 | 근거 / 의도 |
| --- | --- | --- |
| DEC-13 | 방벽·감시탑은 **허용 구역 안에서 그리드 스냅**으로 설치 | 배치 표현을 넓히고 미리보기·불가 위치 표시 요구(5.2)에 맞춘다. 병목 봉쇄에 방벽 여러 개가 필요하도록 조정할 수 있다 |
| DEC-14 | '전멸'은 **파견 인력 포함 전원 사망**일 때만 즉시 패배 | 거점이 비어도 탐사대가 살아 있으면 계속된다. 핵심 시설 피격으로 귀환 전에 질 수 있어 파견 공백의 긴장이 남는다 |
| DEC-15 | 전투 시간 상한 초과 시 **남은 적 1기당 핵심 시설 피해** 후 남은 적을 제거하고 웨이브 종료. HP 0이면 패배 | 먼 곳의 적 하나 때문에 곧바로 지지 않게 하고, 시간 끌기에도 대가를 둔다 |
| DEC-16 | 탐사의 **보상 여부와 사망(최대 1명)은 독립 판정** | '자원은 얻었지만 한 명을 잃었다'가 가능하다. `ExpeditionResolved(reward, casualties)`와 일치한다 |

## 구현 방식

| ID | 확정 결정 | 근거 / 의도 |
| --- | --- | --- |
| DEC-17 | 밸런스 데이터는 **기존 JSON 테이블**(`Resources/Tables`, `TableManager`, `GameTableRules`) 재사용. 샘플 항목은 POC 값으로 교체 | 확정 수치 전부 테이블화, SO보다 JSON 우선 |
| DEC-18 | 씬·프리팹은 **Unity CLI로 직접 제작해 에셋으로 저장**. 씬 생성 빌더 코드를 두지 않는다 | Unity CLI 우선, 프로시저럴 생성 지양. 런타임 생성은 적·효과 스폰과 플레이어가 설치한 시설로 한정 |
| DEC-19 | UI는 **MVP 패턴**, View는 프리팹에 배치 | 작업 지침 3절 |
| DEC-20 | 분석 로그는 **`LogSession` → `FileLogStore`** 최소 구현. 경로는 `Application.persistentDataPath/Telemetry/{sessionId}.jsonl`, sequence 포함. 이벤트는 `POC_CORE.md` 7절의 9종으로 한정 | POC2 로그 계약을 따르되 POC 범위로 줄인다. 슬롯·상점·무기 수집기는 만들지 않는다 |
| DEC-21 | LogKit은 **콘솔·오류 수집만** 담당. 게임 사건을 양쪽에 기록하지 않고, 업로드는 기본 꺼짐, 서버 주소·키는 저장소에 두지 않는다 | POC2 로그 계약 |
| DEC-22 | 템플릿 코드는 **삭제하지 않고** 빌드 시작 씬만 교체. 샘플 데이터와 `SmokeCheck`는 필요한 만큼 수정 | 변경 범위 최소화 |
| DEC-23 | 코딩 스타일(작업 지침 4절)을 **템플릿 코드까지 일괄 적용**. 기능 변경과 섞지 않고 별도 커밋 | 프로젝트 스타일 통일 |

## 구현 중 결정

사용자에게 묻지 않고 에이전트가 정했다. 불변 원칙에 영향이 없고, 바꾸고 싶으면 이 표를 고친다.

| ID | 결정 | 근거 / 의도 |
| --- | --- | --- |
| DEC-28 | **LogKit은 업스트림 v0.7.0을 그대로 쓴다.** 워커가 임베드·패치한 패키지는 되돌렸다. 업로드는 `LOGKIT_SERVER_URL`, `LOGKIT_UPLOAD_KEY`가 **둘 다 있는 PC에서만** 켜진다(값은 저장소에 두지 않는다). 없으면 업로드가 꺼지고, 그런 PC의 빌드는 `LOGKIT_OPTIONAL=1`이 필요하다. 도메인 리로드 없는 Play의 인스턴스 부재는 `LogKitSetup`이 종료 플래그를 되돌려 우회한다 | 승인 없이 의존성을 바꾸지 않는다. 빈 키 경고(키가 있어도 Awake에서 먼저 나옴)와 일시정지 전송 기본값은 업스트림 과제로 남긴다 |
| DEC-29 | **1인 파티가 사망하면 보상 없음.** 보상 판정이 성공해도 가져올 사람이 없다. 2인 이상은 DEC-16대로 독립이다 | 기획 문구와 어긋나지 않는 물리적 예외. 패널 표시를 실제와 맞춘다 |
| DEC-30 | 세션이 끝날 때 진행 중인 탐사는 **결과 없이 끝난다.** 로그에 짝 없는 `ExpeditionStarted`가 남을 수 있다 | 세션 종료 뒤의 결과는 게임에 영향이 없다. 분석할 때 이렇게 해석한다 |
| DEC-31 | 밸런스 값은 `GameplayTableData.json`이 기준이다. `POC_CORE.md` 4절의 수치는 **제안 초깃값**으로 남긴다. 조정 이력과 근거는 [`BALANCE_REPORT.md`](BALANCE_REPORT.md) | 4절이 가변 파라미터로 정의돼 있어 원문을 고치지 않는다 |

## 작업 지침 적용 범위

POC2 작업 지침과 로그 문서에서 씬 순서, JSON 테이블, MVP, 프로시저럴 생성 지양, 코딩 스타일, 커밋 형식, 로그 계약만 적용한다. 슬롯머신, 상점, 무기, 소지금 항목은 이 게임에 없어 적용하지 않는다.
