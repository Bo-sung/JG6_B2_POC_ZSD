# Unity POC v2 — 기존 POC 후속 구현 실행 프롬프트

아래 작업을 **현재 완성되어 있는 Unity POC 프로젝트에 증분 적용**하세요. 신규 프로젝트 생성이나 구조 전면 재작성은 요구하지 않습니다.

## 필수 문서(착수 전 읽기)

1. `POC_CORE.md` — **v1 기준선**. 최소 0절·2절(INV-01~08)·3절·7절·8절을 읽으세요.
2. `POC_V2_SCOPE.md` — **v2 확장 기준서**. 전체를 읽고, 특히 0절(압축 후 보존), 2절(기존 결정과의 충돌), 4절(상세 규칙), 7절(수락 조건), 8절(결정 기록)을 구현의 기준으로 삼으세요.

**문서 우선순위:** 사용자 최신 명시 지시 > v1의 불변 원칙(INV-01~08) > v2의 명시적 변경 결정 > v1의 충돌하지 않는 상세 결정 > 기존 코드(실제 구현 확인) > 원본 기획 저장소. v1 문서를 임의 수정하거나 v2 내용을 v1의 예전 결정과 혼동하지 마세요.

## 작업 목표

기존 v1의 `생산/탐사/방어 사이의 인력 배분 → 실시간 방어 → 영구 사망 → 다음 운영` 루프를 유지하면서, **`신규 인력 확보 → 활동을 통한 숙련 → 부상/치료 또는 사망 → 전력 재편성`** 루프를 추가합니다.

## 작업 순서

1. **실태 확인 (G0):** 실제 프로젝트의 Unity 버전, 씬, 데이터 구조, 생존자 ID, 인력 배정, 웨이브, 탐사, 전투, 테스트 수단을 조사하세요. 사용자에 따르면 v1 구현은 완료됐지만, 코드 확인 없이 완료 상태를 추측하지 마세요. 기존 기능을 실행/검증하고 v2 변경 지점을 보고하세요.
2. **인력 수급 기반 (G1):** 초기 7명/최대 9명, 웨이브 2·4 준비 시작의 방문자, 스크랩 비용, 영입/거절과 **공통 신규 인력 생성 경로**를 구현하세요. 탐사 구조는 G3에서 이 경로에 연결하세요. 신규 인력도 작업·방어 이중 배정과 영구 사망 규칙을 따르게 하세요.
3. **부상·치료 (G2):** 자동 HP 완전 회복을 제거하고 HP/정상·경상·중상 상태를 다음 웨이브로 이월하세요. 시작 배치 치료소 1개, 치료 담당자·대상 지정, 스크랩·시간 비용, 경보 시 치료 중지/재개를 연결하세요. 중상자 방어 불가 및 기존 배정 보존을 확인하세요.
4. **탐사 이벤트 (G3):** `생존자 발견`, `추가 보급품`, `적대 생물 조우` 3종을 기존 탐사 패널에 추가하세요. **상황 기반의 실행/계속/철수 판단**이지 증강·보상 카드 선택이 아닙니다. 이벤트/구조 결과는 같은 파견에서 **정확히 한 번** 정산하고 전투 시간이 멈추지 않도록 하세요.
5. **성장·특성 (G4):** 기존 3개 능력치에만 활동별 XP와 제한된 +1 성장, 3개 특성(최대 1개)을 추가하세요. 사망 시 성장 정보도 소실하고 무한 XP 파밍이 되지 않도록 하세요.
6. **6웨이브 및 통합 (G5):** 현재 적 2종·방벽/감시탑·스크랩 자원·단일 거점은 유지하고 6웨이브까지 인력/부상/치료/성장/자원/시설/탐사 상태가 이월되게 하세요. HUD·결과 패널·로그를 최소한으로 확장하세요.
7. **회귀 및 검증 (G6):** v1 불변 원칙과 `POC_V2_SCOPE.md` 7절 체크리스트·엣지 케이스를 검사하세요. 실제 플레이로 확인하지 않은 재미 가설을 '검증 완료'라고 쓰지 마세요.

## 의도적으로 하지 말 것

- 차원 소환 가챠, 폐교/세계관 구현, 신규 탐사 전투 맵, 추가 적/방어 시설, 장비/복합 자원 경제, 스킬 트리, 전문 의료 능력치, 대규모 프레임워크/전체 리라이트.
- 인력이 무한 무료 충원되는 구조, 사망 인력 부활·대체 ID 재사용, 중상자 전투 참여, 치료 중 자원·작업 시간 중복 사용.
- 작업/방어 이중 배정을 지우거나 '3개의 강화 카드 중 하나 선택' 같은 외부 선택 UI로 바꾸는 일.
- 실제 Unity 씬/코드/테스트 근거 없이 기능을 구현했다고 보고하는 일.

## 의사결정 및 컨텍스트 압축 처리

- 수치(방문 빈도, 수급비, HP 임계값, 성장 속도, 치료 시간, 이벤트 확률)는 `POC_V2_SCOPE.md`의 **초기값**으로 시작하되, 플레이/테스트 결과에 따라 조정할 수 있습니다.
- 새로운 도메인 결정, 기존 불변 원칙과 충돌, 구현 범위 확장 이슈는 **결정 로그에 제안**하고 승인 없이 핵심 규칙을 바꾸지 마세요.
- **컨텍스트 압축/세션 변경 시** 가장 먼저 `POC_CORE.md`의 0·2·8절과 `POC_V2_SCOPE.md`의 0·2·7·8절을 다시 읽고, 진행 중인 게이트와 실제 작업 트리 상태를 확인하세요.
- 외부 워커/하위 에이전트가 있다면 각자 담당 기능뿐 아니라 **인력 공유·영구 손실·수용 상한·중복 정산 방지** 규칙을 함께 전달하세요.

## 최종 보고 형식

- **현재 프로젝트/기존 기능 확인:** 버전·씬·재사용한 클래스와 v1 회귀 상태
- **구현 결과:** G0~G6 각 단계 완료/미완료 및 실제 증거
- **새 기능 동작:** 방문/구조/성장/부상/치료/이벤트/6웨이브의 플레이 흐름
- **테스트:** 수락 체크리스트 통과 여부, 엣지 케이스, 고정 시드/재현 절차
- **핵심 경험 검증:** 관찰된 사실과 아직 플레이테스트하지 못한 가설 분리
- **결정·제약:** 변경한 가변 수치, 문서 충돌, 후속 작업

**최상위 목표:** 인력을 수급할 수 있는 상황에서도 인력의 성장·부상·영구 손실이 계속 의미를 갖고, 그 결과가 다음 방어전과 생산·탐사 운영을 변화시키는 **플레이 가능한 Unity POC v2**를 완성하는 것.
