## 0. 컨텍스트 압축 보존 블록 (READ FIRST / NEVER DROP)

**이 절은 모든 구현 에이전트·워커·인계 요약·컨텍스트 압축 후에 반드시 다시 확인한다. 이 문서와 v1 `POC_CORE.md`의 0절을 함께 읽는다.**

1. **게임의 핵심:** 한정된 개별 인력을 **생산·탐사·방어에 경쟁적으로 배분**하고, 준비의 결과가 실시간 RTS 방어에 나타나며, **영구 사망**이 다음 운영을 바꾼다.
2. **v2 검증 경험:** **새 인력 확보 → 작업/전투/탐사 경험 축적 → 부상/회복 또는 영구 손실 → 재배치/재편성**의 순환이 전략과 애착을 만드는지 검증한다.
3. **생존자 동일성:** 모든 인력은 고유 ID·능력치·상태·작업/방어 배정을 가지며 **기존 7명과 신규 합류 인력은 정확히 같은 규칙**을 따른다. 사망자는 절대로 복귀/치료/재영입되지 않는다.
4. **수급 방식:** **거점 방문**과 **탐사 중 구조**, 두 가지만. 자동 무제한 충원이나 가챠가 아니다. 스크랩 비용·수용 상한·파견 위험으로 대체 인력의 기회비용을 만든다.
5. **부상:** v1의 '웨이브 종료 시 생존자 HP 완전 회복' 규칙을 **폐지**한다. HP와 부상은 웨이브를 넘어 지속하고, 치료에는 인력·시간·스크랩이 필요하다. HP=0은 영구 사망이다.
6. **성장:** `전투/작업/탐사` 3개 능력치만 유지하고 경험치 및 단순 특성만 추가한다. 복잡한 스킬트리·장비·장기 육성 체계는 추가하지 않는다.
7. **탐사 이벤트:** 탐사 중 **생존자 발견 / 추가 보급품 / 적대 생물 조우**의 3종만. 선택은 해당 탐사와 인력 상태 때문에 발생하는 **맥락적 대응**이며 뱀서류의 보상 카드·랜덤 증강 선택이 아니다.
8. **실험 크기:** 동일 거점·초기 인력 **7명**, 수용 상한 **9명**, 적 2종·전투 시설 2종·스크랩 자원 1종을 기본 유지하고 **3웨이브 → 6웨이브**로 늘린다. 데이터/시간 값은 가변이다.
9. **이중 배정·경보 자동 이동·전투 직접 명령·탐사와 전투의 시간 중첩·탐사 중 인력의 방어 불참은 그대로 유지**한다. 부상/사망/신규 합류도 이 규칙을 우회해서는 안 된다.
10. **v2에서 검증할 것:** 충원이 손실의 긴장감을 없애지 않는가? 누굴 키우고 보호할지 달라지는가? 부상자를 치료할지 다른 곳에 인력을 쓸지 고민하는가? 탐사 상황에 따라 실제 행동을 바꾸는가?
11. **새 범위를 임의 확대하지 않는다.** 차원 소환, 상세 의료 스탯, 식량·물·연료, 거점 확장, 새로운 적·방어시설, 장비, 별도 탐사 씬, 전체 세이브 시스템은 후속 후보로 보류한다.
12. **문서 위계:** 사용자 최신 명시 지시 > `POC_CORE.md`의 `INV-01~08` > 본 v2의 명시적 변경 결정 > v1의 충돌 없는 상세 규칙 > 현재 프로젝트의 기존 구현(불일치 발견 시 보고) > 원본 기획 저장소. 압축 후엔 이 문서를 재독한다.

## 2. v1과의 관계 — 변경 통제

### 2.1 불변 원칙 유지

`POC_CORE.md`의 `INV-01~08`은 계속 **불변**이다. 신규 인력·부상·치료를 도입하더라도 다음을 지킨다.

- **하나의 인력 풀**: 작업/치료/탐사/방어에 인력을 중복 실사용하지 않는다.
- **작업·방어 이중 배정**: 배정 데이터는 독립 보존. 탐사·부상·사망은 실제 실행 가능 여부에만 영향.

- **영구 사망의 비가역성**: 인력이 새로 들어와도 기존 사망자가 되돌아오는 것은 아니다.
- **행위 기반 의사결정**: 생산·치료·파견·배정·건설·이벤트 대응으로 선택. 보상 카드/증강 선택으로 치환 금지.
- **짧고 재현 가능한 실험**: 시작 시드와 초기 조건, 주요 이벤트 로그, 재시작/속도 조절 지원.

### 3.1 크기 및 일정 가정

- 기존 **거점 맵 1개**, 초기 인력 **7명**, 현재 보유 인력 상한 **9명**.
- **6웨이브**, 1회 플레이 **20~30분 목표**. 실제 소요 시간은 구현 상태에 따라 변경 가능하며 수락 조건은 아니다.
- 기존 **스크랩 1종**, 방벽/감시탑 + 생산 시설 유지. **치료소 1개는 v2에서 사전 배치**하고 건설 메뉴에는 추가하지 않는다.
- 탐사 지역은 기존 2곳, 적 유형도 기존 2종 유지. 방어 지형의 최소 2개 진입로 유지.
- 새 인력·경험치·이벤트의 확률/비용/시간 수치는 **초깃값**이며 불변 조건이 아니다.

## 4. 기능별 상세 규칙 및 명시적 의사결정

### 4.1 인력 수급 — 최우선(P0)

**두 수급 경로 모두 기존 `Survivor` 엔터티와 배정/전투/탐사 시스템을 그대로 이용한다.** 새 NPC나 파견 구조로 들어온 인력을 특수한 예외 유닛으로 만들지 않는다.

#### A. 거점 방문

- **기회 발생:** 시작 기준 **웨이브 2와 4의 준비 시작 시** 각 1명의 방문 후보를 제공한다. 이는 테스트용 일정이며 조정 가능하다.
- **표현:** 기존 메인 거점 입구에 방문자 마커/NPC 또는 HUD의 '방문자 도착' 항목으로 나타난다. **실제 월드의 거점 운영 중 발생하는 사건**으로 취급하며 별도 랜덤 보상 카드 화면이 아니다.
- **조작:** 방문자 선택 → 이름/기본 능력/특성/영입 비용 확인 → `영입` 또는 `보내기` 결정. 방치 시 해당 준비 단계 종료와 함께 기회 소멸.
- **비용:** 영입 시 스크랩 **5개**(초기 조정값). 시설·치료에도 같은 스크랩을 사용하게 하여 비용 경쟁 유도.
- **수용 상한:** 살아 있는 보유 인원 **9명**. 9명인 경우 영입 불가능. 파견 중 인력과 중상 인력도 **보유 인원에 포함**하며, 사망자는 제외한다.
- **합류 규칙:** 영입 성공 시 HP 최대/정상 상태, 배정 미설정 상태로 거점 안전 지점에 생성. 플레이어가 작업/방어 배정을 지정한 후 효율적으로 동작한다. **자동으로 전투 슬롯을 차지시키지 않는다.**
- **방문 후보:** 사전 정의된 인력 유형/이름/능력치/특성에서 시드 기반 결정. 플레이마다 변화는 허용하지만 같은 시드면 후보와 시점을 재현할 수 있어야 한다.
- **거절/자원 부족:** 불가능 사유를 명시하고 자원 차감이나 인력 생성이 일어나지 않는다.

#### B. 탐사 중 생존자 구조

- 기존 2개 탐사 지역에서 **`생존자 발견` 이벤트**를 통해 구조 기회를 얻는다. 무조건적인 보상 인력 지급은 아니다.
- `구조 시도`: 현재 파견 팀의 능력치/규모에 따른 위험 판정과 추가 시간 비용을 치른다. 성공 시 **신규 생존자 1명**을 귀환 시점에 함께 데려온다. 성공하지 못하면 인력 합류는 없고 위험 결과는 별도로 적용.
- `기존 임무 계속`: 구조를 포기하고 본래 탐사 목표를 계속한다.
- `철수`: 가능한 경우 현재 탐사를 중단하고 귀환한다. **강제 교전 중에는 바로 철수할 수 없다.**
- 구조 성공 시점에 당장 인력을 생성하지 않는다. 대신 **구조 성공 시점에 수용 인원 1칸을 예약**하고, **귀환 결과 정산 시에만 실제 합류**한다. 이 예약은 방문 영입·다른 탐사의 구조 시도에서도 상한 판정에 포함한다. 그 전에 탐사팀이 전멸하면 구조 성공 보상은 사라지고 예약도 해제한다.
- 수용 상한 9명을 초과할 수 없다. 방문 영입 및 구조 시도 모두 **현재 보유 인원(파견·중상 포함) + 예약된 귀환 예정 구조자 수**를 기준으로 판정한다. **상한이 찼으면 구조 시작 불가**(구조 결과를 임의로 소멸시키지 않음).
- 구조 인력에게도 동일한 고유 ID, 능력치, 성장, 부상, 영구 사망 규칙을 적용한다.

#### 인력 수급의 밸런스 경계

- 신규 충원은 **손실 복구의 가능성**이지 무조건적인 복원이 아니다. 사망한 숙련자의 성장치/특성을 자동 승계하지 않는다.
- 항상 영입만 하면 유리하거나, 항상 영입을 포기하는 것이 유리하면 경제·기회 빈도·후반 난이도를 조정한다.
- 인력 수급이 단순 랜덤 가챠의 보상 선택으로 전환되면 설계 목적에서 벗어난다.

### 4.2 성장·특성(P0)

- 기존 능력치 **`Combat/Work/Exploration` 3개(기본 범위 1~5)** 유지. 각 능력치는 해당 활동 수행으로 **개별 XP** 획득.
- `Combat`: 실제 방어전 참여/유효 공격·웨이브 종료에 따른 제한적 XP. `Work`: 실제 스크랩 생산/치료 작업 수행에 따른 XP. `Exploration`: 탐사 귀환/이벤트 대응 결과에 따른 XP.
- **경험치 악용 금지:** 대기, 반복 클릭, 아무 행동 없이 시간만 경과로 XP를 무한 지급하지 않는다. 웨이브/탐사 건당 XP 상한 설정.
- 초기 구현은 **능력치 +1 성장**만 도입하며 상한은 **5**로 유지한다. 장기 스킬 트리와 별도 레벨링은 구현하지 않는다.
- **특성은 최대 1개**: `사격 전문`(전투 효율 +20%), `숙련 작업자`(작업 효율 +20%), `정찰 전문가`(탐사 효율/안전 +20%)의 3종. 이 수치는 조정 가능. 특성 없는 인력도 존재.
- 특성은 기본적으로 **초기/영입 시 부여**하고 v2에서 특성 획득·합성·중복 강화 시스템은 만들지 않는다.
- 성장 결과는 캐릭터 선택 패널과 웨이브/탐사 결과에 나타난다. 사망 시 XP와 특성도 즉시 소실한다.

### 4.3 부상·치료(P0)

**HP 감소 → 부상 상태 → 행동 제약 → 치료에 자원·인력 투입**이 드러나야 한다. 상태는 HP에서 **파생**하고 별도 동기화 실패를 만들지 않는다.

| HP 범위(최대 HP 대비) | 상태 | 실제 영향 |
| --- | --- | --- |
| **70% 이상** | 정상 | 기존 성능 유지 |
| **30% 이상 ~ 70% 미만** | 경상 | 전투·작업·탐사 가능, 해당 효율 **-25%**(초기값) |
| **0% 초과 ~ 30% 미만** | 중상 | **작업·탐사·방어 불가**. 치료 대기 또는 치료 중 |
| **0** | 사망 | **영구 제거**. 치료/부활/신규 인력으로 동일 개체 복구 불가 |

- **웨이브 종료 HP 완전 회복 제거.** 평시와 다음 웨이브에 이전 피해가 지속된다.
- **치료소 1개**를 처음부터 거점에 배치한다. 치료는 **준비 단계**에만 가능하다.
- 치료 시작에는 (1) **행동 가능한 치료 담당자 1명**, (2) 환자 선택, (3) 스크랩 **2개(초기값)**가 필요하다. 치료 담당자는 치료 중 생산·탐사·방어 대기 업무를 동시에 수행하지 못한다. **다음 경보 시 치료를 중지하고 저장된 방어 배정으로 이동**한다.
- 최초 단순 규칙: 치료 1회당 HP **40%p 회복**(상한 100%, 초깃값), 기본 **20초** 소요. 담당자의 `Work` 능력에 따라 속도 보정. 치료 진행 도중 경보가 울리면 **진행률 보존 후 일시정지**, 재개 시 추가 비용 차감 없음. 실제 완료했을 때 HP를 회복한다.
- **중상자는 방어 위치 지정 데이터는 유지**하지만, 행동 불가이므로 경보에서 이동하지 않는다. 치료로 경상 이상이 되면 정상적인 배정 및 이동이 다시 가능해진다.
- **전투 중 치료/즉시 부활/체력 자동 리셋 없음**. 사망자·파견 중인 인력은 치료 불가능.
- 탐사 사건으로 부상도 발생할 수 있고, 탐사 중 부상 결과는 귀환 또는 사건 해결 시점에 반영한다. 탐사 중 HP가 0이 되면 동일한 영구 사망 처리.

### 4.4 탐사 이벤트(P0)

기존 '탐사 파견 → 타이머 → 결과' 구조에 **이벤트 3종만 추가**한다. **별도 3D 탐사 씬 제작 없음.**

| 이벤트 | 타입 | 조작/처리 | 시스템 결과 |
| --- | --- | --- | --- |
| 생존자 발견 | 선택 | 구조 시도 / 임무 계속 / 철수 | 인력 수급 기회, 위험·시간 증가 |
| 추가 보급품 발견 | 선택 | 추가 수색 / 임무 계속 / 철수 | 스크랩 기대 보상 증가, 시간·위험 증가 |
| 적대 생물 조우 | 강제 | 간단한 능력치·위험 판정 후 자동 해결 | HP 피해·귀환 지연·사망 가능 |

- **사건이 발생한 이유와 현재 파견 인력 상태가 보이는** 기존 탐사 패널 내 상황 알림으로 표현한다. 랜덤 보상 카드처럼 플레이어 능력 자체를 강화하는 UI는 만들지 않는다.
- 선택 사건 대기 중 전체 게임이나 웨이브 시간이 **자동 정지하지 않는다.** 전투 중도 이벤트가 도착할 수 있으므로 경고와 미응답 처리(예: 15초 후 '임무 계속')를 정의한다. 실제 기본값과 타임아웃 방식은 UI 테스트를 통해 조정 가능하다.
- 강제 사건은 선택 없이 결과를 처리한다. '퇴각 불가' 제약을 유지하되, 강제 사건 종료 뒤 기존 파견 명령을 계속하거나 귀환할 수 있다.
- 한 번의 탐사에서 **최대 1건의 주요 이벤트**가 발생하도록 시작한다. 이벤트 발생 여부/유형은 시드 기반으로 재현한다.
- 방문자 수급과 탐사 구조는 **서로 다른 방식으로 동일한 인력 풀을 확장**하며, 모집 완료 순간에도 이중 배정·수용 상한이 일관되게 적용된다.

### 4.5 6웨이브 및 상태 이월(P0)

- 기존 W1~W3 규칙은 가능한 한 유지하고, W4~W6은 기존 **일반형/돌파형 2종**의 수량/배치를 바꿔 난도를 단계적으로 높인다. 새 적/보스 추가 금지.
- 기본 반복은 **준비 → (탐사/방문/작업/치료/건설) → 경보 → RTS 방어 → 손실/획득/성장 정산 → 다음 준비**.
- 다음 웨이브로 **인력(사망/신입 포함), HP, XP, 특성, 작업·방어 배정, 스크랩, 시설 파손, 탐사 진행**이 유지된다.
- 소수 인원이 사망했다고 강제 종료하지 않는다. **기존 v1의 패배 조건(핵심 시설 파괴 또는 전멸)**을 유지한다.
- W6을 방어하면 성공. 결과 화면에 **초기/추가/사망/최종 인원**, 사망자 ID/이름, 남은 HP/자원, 성장 결과, 탐사 이벤트·영입 기록을 요약한다.
- 동일 시드로 방문 후보·탐사 이벤트·웨이브 결과의 재현성을 검증하되, AI/물리 시뮬레이션의 수치적 완전 동일성까지 보장한다고 주장하지 않는다.

### 기술·데이터 구현 경계

- **기존 Unity 프로젝트가 기준**: 현재 버전·패키지·씬·자료구조를 조사한 후 최소 변경한다. Unity 6/URP/C#이라는 원래 목표는 유지하되 기존 프로젝트와 충돌할 때 실제 환경을 먼저 확인한다.
- `Survivor` 고유 ID/상태/능력치에 신규 합류·XP·HP 파생 상태를 연결한다. 인력 생성 경로를 **공통화**하여 방문/구조/초기 인력 간 처리 차이를 최소화한다.
- `Assignment`는 **지속 데이터**, `CurrentActivity`는 **현재 행동**으로 분리한다. 치료·탐사·중상은 행동 가능 여부만 제한한다. 의료 작업자를 전시 배정에서 삭제하지 않는다.
- `Expedition` 이벤트는 `pending/resolved` 상태를 가진다. 귀환 보상/구조 인력/피해를 **딱 한 번 정산**하는 중복 방지(idempotency)가 필수.
- HP 사망 처리/인력 수용 상한/스크랩 비용 차감은 **단일 권위 경로**에서 수행하고 UI·게임 로직이 각자 중복 처리하지 않는다.
- 데이터 수치와 후보/이벤트/웨이브 구성은 기존 ScriptableObject/직렬화 설정을 우선 재사용하고, 데이터 저장 방식을 새로 만드는 작업은 피한다.
- 테스트 로그는 기존 형식을 확대한다. 별도의 분석 웹사이트/DB 인프라를 만들지 않는다.

## 7. 검증 방법과 수락 기준

### 7.1 기능 수락 조건(필수)

- [ ] **기존 v1**의 생산/탐사/방어 인력 경쟁, 작업·방어 이중 배정, 경보 이동, 명령, 탐사 중첩, 시설 효과, 영구 사망을 회귀 테스트로 통과한다.
- [ ] **거점 방문**: 정해진 준비 시점에 등장하며, 영입/거절·스크랩 비용·상한 판정이 정상이다.
- [ ] **탐사 구조**: 이벤트로 발견/구조 시도 후 성공한 경우 **귀환 시 한 번만 합류**한다. 대기 중/실패/전멸 시 유령 인력이 생성되지 않는다.
- [ ] **인력 상한**: 파견/중상 인력까지 세어 **9명 초과 불가**. 동시에 방문 수급과 탐사 수급이 발생해도 상한 위반이 없다.
- [ ] **영구 사망**: 죽은 숙련자가 회복되거나 새 영입 인력의 ID/경험치/특성을 승계하지 않는다.
- [ ] **부상**: 웨이브 종료 후 HP가 자동 회복되지 않고, 경상 페널티·중상 행동 제한이 실제 결과에 영향을 준다.
- [ ] **치료**: 담당자/자원/시간이 필요하고, 경보 시 치료 담당자는 방어로 전환·중상자는 대기, 완료 시 정상/경상으로 복귀 가능하다.
- [ ] **성장**: 세 능력치 경험치·성장이 행동과 연계되어 표시되고, 반복 클릭/대기로 무한 성장하지 않는다.
- [ ] **이벤트**: 3종 사건이 발생·해결되며 선택형/강제형의 처리와 타임아웃이 정의되어 전투 진행을 막지 않는다.
- [ ] **6웨이브**: 시작부터 승리/패배까지 완결되고 인력/HP/성장/자원/시설/탐사가 적절히 이월된다.
- [ ] **재현/로그**: 재시작 및 시드 지정 가능, 방문/충원/치료/성장/사망/이벤트/웨이브가 기록된다.

### 7.2 반드시 테스트할 엣지 케이스

1. 파견 중 사망/중상/방문 합류와 전투 경보가 비슷한 시각에 발생한다.
2. 9명 상태에서 구조 성공 또는 방문 영입이 발생한다(중복 예약·상한 초과 금지).
3. 마지막 행동 가능한 인력이 의료 담당자일 때 경보가 발생한다.
4. 중상자가 치료로 경상이 된 직후 배정은 남아 있고 정상 명령을 수행한다.
5. 치료 비용 차감 후 경보로 중단했다가 재개한다(이중 차감 없음).
6. 탐사 이벤트를 무시한 채 전투가 시작되거나, 동일 사건 콜백이 두 번 호출된다(한 번만 정산).
7. 탐사 구조자와 방문자가 동일한 신규 인력 ID를 받지 않는다.
8. 마지막 웨이브 중 전멸/코어 파괴와 클리어가 거의 동시에 발생한다(기존 승패 우선순위 보존).

### 7.3 재미 검증: 구현 완료와 구분한다

| 질문 | 관찰할 행동/로그 | 불합격 신호 |
| --- | --- | --- |
| 신규 충원이 영구 손실과 양립하는가? | 영입/거절 사유, 사망 후 인력 재편성, 방어시설 비용 포기 | 새 인력이 공짜로 무한 공급되어 사망이 무의미 |
| 숙련 인력이 보호 대상이 되는가? | 재능 높은 인력의 탐사 기피·방어 후퇴·대체 인력 투입 | 능력치 성장/특성이 결과에 영향 없음 |
| 치료가 기회비용을 만드는가? | 치료 중 작업/방어 공백, 자원 사용, 다음 웨이브 계획 | 치료가 언제나 무료/즉시이거나 항상 무시됨 |
| 탐사 이벤트가 전략을 바꾸는가? | 구조 시도/추가 수색/철수에 따른 팀 상태·귀환 시간 | 사건 선택의 후속 차이가 사실상 없음 |
| 긴 세션의 전략 변화가 재미있는가? | W1~W6 인력 분포·부상·영입·사망·시설 배치 변화 | 초반 동일 전략을 반복해도 전부 해결됨 |

**테스터 5명 내외의 탐색적 평가**를 권장한다. 소표본 설문 수치는 통계적 증명이 아니다. 성공 판정은 플레이를 관찰한 뒤 구체적인 원인-결과를 근거로 한다. 데이터 없는 '재미 검증 성공' 보고 금지.

## 9. 작업 인수인계 및 컨텍스트 복구

1. **신규 세션**에서는 `POC_CORE.md`의 0·2·8절과 **본 문서 0·2·4·7·8절**을 읽는다.
2. 현재 저장소의 실제 구현 상태(기존 기능, 빌드, 테스트, 씬/스크립트)를 조사한다. 사용자의 'v1 완료' 진술을 믿되, 어떤 부분이 구현됐는지는 직접 확인한다.
3. 작업 시작 전에 **v1과 충돌하는 5개 DEC**를 명확히 식별한다. `INV-01~08`은 변경 대상이 아니다.
4. G0~G6 순으로 기존 코드를 **증분 수정**하고 매 게이트에서 실제 씬/빌드/실행 테스트로 확인한다.
5. 워커마다 동일 원칙(인력 풀, 영구 사망, 이벤트 맥락, 상한·중복 방지)을 전달한다. 역할 경계를 넘는 임시 패치는 금지.
6. 문서에 없는 추가 기능·충돌하는 새 결정은 임의 확정하지 않는다. 가변 수치는 테스트 근거와 함께 수정하고, 핵심 기능 변경은 결정 로그에 남긴다.
7. 작업 종료 시 **동작 검증**, **미완성**, **미검증 재미 가설**, **남은 제약**, **수정한 결정**, **정확한 재현 방법**을 분리 보고한다.
